# 사이키봇

Discord 서버의 회의 음성 출석을 확인하고, 공지 수신에 동의해 역할을 받은 멤버에게만 DM 공지를 보내는 봇입니다. 불참자는 목록과 멘션으로 보여주며, 서버 멤버를 자동으로 추방하지 않습니다.

## 기능

| 명령어 | 용도 | 권한 |
| --- | --- | --- |
| `/사이키도움말` | 명령어와 수신 정책 안내 | 관리자 + 봇 사용 허용 역할 |
| `/회의불참자목록` | 지정한 음성 채널에 없는 역할 멤버 목록 및 멘션 | 관리자 + 봇 사용 허용 역할 |
| `/공지수신 설정` | DM 공지 수신 동의 또는 철회 | 모든 멤버 |
| `/공지수신현황` | 동의·미동의 멤버 수와 페이지별 명단 확인 | 관리자 + 봇 사용 허용 역할 |
| `/dm전송 내용` | 수신 동의 멤버에게 미리보기 확인 후 DM 발송 | 관리자 + 봇 사용 허용 역할 |
| `/봇사용역할설정` | 명령어 사용 허용 역할 최대 10개 지정 또는 초기화 | 서버 관리자 전용 |

## 요구사항

- Node.js 20 이상
- Discord Developer Portal에서 만든 봇 애플리케이션과 봇 토큰
- 봇 애플리케이션의 **Server Members Intent** 활성화
- 서버에 봇을 초대할 때 `bot`, `applications.commands` OAuth2 scope 선택

Developer Portal에서 애플리케이션과 봇 사용자 이름을 `사이키봇`으로 설정하세요.

### 봇 권한

- `View Channels`: 회의 음성 채널과 명령어 실행 채널을 볼 수 있어야 합니다.
- `Send Messages`: 출석 결과와 공지 미리보기를 응답 채널에 표시합니다.
- `Embed Links`: `/사이키도움말` 안내를 표시합니다.
- `Manage Roles`: 서버 입장 시 공지 수신 역할을 자동 생성·배치하고 `/공지수신` 동의 역할을 사용자에게 부여하거나 철회합니다.

봇이 서버에 초대되면 `사이키봇 공지 수신` 역할을 자동으로 만들거나 찾고, 봇이 관리할 수 있도록 봇 역할 바로 아래에 배치합니다. 기존 서버에서도 `/공지수신` 또는 `/dm전송`을 처음 실행할 때 같은 준비를 합니다. 여러 명이 동시에 실행해도 역할은 중복 생성되지 않습니다. 자동 준비를 위해 초대 시 봇에 `Manage Roles` 권한을 부여하세요. Discord는 봇이 자기 자신의 관리 역할을 움직이는 것을 허용하지 않으므로, 역할 순서상 자동 배치가 불가능한 서버에서는 관리자가 봇 역할을 위로 올려야 합니다. 출석을 확인할 음성 채널에 봇의 `View Channel` 권한이 있어야 합니다. 서버 멤버 목록을 가져오려면 Developer Portal의 **Bot → Privileged Gateway Intents → Server Members Intent**를 켜야 합니다.

## 설치 및 설정

PowerShell에서 프로젝트 폴더로 이동한 다음:

```powershell
npm install
Copy-Item .env.example .env
```

Discord Developer Portal에서 다음 값을 확인해 `.env`에 입력합니다.

- `DISCORD_TOKEN`: Bot 페이지에서 발급한 토큰. 다른 사람에게 공개하지 마세요.
- `DISCORD_CLIENT_ID`: General Information 페이지의 Application ID. 슬래시 명령어 등록 시 필요합니다. 봇 로그인만 할 때는 생략할 수 있습니다.
- `DISCORD_GUILD_ID`: 선택 사항입니다. 설정하면 해당 서버에 명령어를 바로 등록합니다. 비워 두면 전역 명령어로 등록하며 Discord 반영까지 시간이 걸릴 수 있습니다.

`.env`에 토큰만 입력해도 봇은 로그인할 수 있습니다.

```powershell
npm start
```

봇 명령어를 사용하려면 Application ID도 `.env`에 입력한 뒤 한 번 실행해 등록합니다.

```powershell
npm run register
npm start
```

슬래시 명령어를 추가하거나 변경할 때도 `npm run register`를 다시 실행하세요. 특정 서버에 즉시 등록하려면 `npm run register -- 서버ID`를 실행합니다. 이 경우 해당 서버의 기존 서버별 명령어 목록을 현재 코드의 명령어 목록으로 교체하고, 등록된 옵션을 터미널에 표시합니다. 전역 명령어는 Discord에 반영되는 데 시간이 걸릴 수 있습니다. 터미널에 `사이키봇 로그인 완료`가 표시되면 로그인된 상태입니다. 배포 환경에서는 프로세스 관리자를 사용해 종료 시 재시작되도록 운영하세요. 토큰이 노출되었다면 Developer Portal에서 즉시 재발급하세요.

슬래시 명령어는 실행 즉시 공개 응답을 예약해 Discord 상호작용 만료를 방지하고, 작업이 끝나면 같은 응답을 결과로 갱신합니다. 공지 수신 동의·철회 여부, DM 공지 미리보기와 발송 진행 결과도 명령어를 실행한 채널의 모든 멤버에게 표시됩니다. 멤버 목록 조회나 DM 발송 등 네트워크 작업의 최종 결과까지 2초 이내로 보장할 수는 없습니다.

### 봇 명령어 사용 역할 제한

서버 관리자가 `/봇사용역할설정`에서 `역할1`부터 `역할10`까지 허용 역할을 지정합니다. `/공지수신`을 제외한 명령어와 관련 버튼은 **관리자 권한과 지정된 역할 중 하나 이상을 모두 보유해야** 사용할 수 있습니다. 일반 멤버는 허용 역할이 있어도 관리자 명령을 사용할 수 없습니다. 관리자라면 허용 역할 설정 명령으로 접근 역할을 설정하거나 복구할 수 있습니다. 설정은 서버별로 `data/command-access.json`에 저장되어 봇 재시작 후에도 유지됩니다.

새 허용 목록으로 교체하려면 `/봇사용역할설정 역할1:@역할 역할2:@다른역할`처럼 실행하세요. `초기화:true`를 선택하면 허용 목록이 제거되어 `/공지수신`과 관리자 전용 `/봇사용역할설정`만 사용할 수 있습니다. 허용 역할 변경은 즉시 적용됩니다.

## 사용 방법

### 회의 불참자 확인

회의가 진행 중인 서버 채널에서 `/회의불참자목록`을 실행하고 회의 음성 채널과 대상 역할을 선택합니다. 선택한 역할 멤버 중 음성 채널에 접속하지 않은 불참 인원을 먼저, 접속한 참여 인원을 다음으로 이름순 정리해 모두 멘션합니다. 봇 계정은 목록에서 제외됩니다. 멤버가 많아 Discord 메시지 길이를 넘으면 여러 메시지로 나눠 표시합니다.

### DM 공지

1. 멤버가 `/공지수신 설정:동의`를 실행하면 공지 수신 역할을 받습니다. `설정:철회`를 실행하면 역할이 제거됩니다.
2. 관리자이면서 봇 사용 허용 역할도 가진 사용자는 `/공지수신현황`으로 동의·미동의 인원 수와 명단을 확인할 수 있습니다. 명단이 여러 페이지면 버튼으로 이동하며, 목록의 멘션은 알림을 보내지 않습니다.
3. 관리자이면서 봇 사용 허용 역할도 가진 사용자는 `/dm전송`에서 공지 내용을 입력합니다. 봇은 `사이키봇 공지 수신` 역할 보유자에게만 보냅니다.
4. 봇이 해당 역할 보유자 수와 공지 미리보기를 보여줍니다. 공지를 시작한 관리자(허용 역할 보유)가 **보내기** 버튼을 눌러야 DM 발송이 시작됩니다.
5. 봇은 대상 각 멤버에게 개인 멘션을 포함한 DM을 보내며, 발송 중 진행률과 성공·실패·건너뜀 수 및 최종 결과를 표시합니다.

선택한 역할을 가진 멤버만 공지 대상으로 처리됩니다. DM은 각 수신자 멘션과 함께 전송되며, 개인 설정에 따라 전달이 실패할 수 있습니다. 발송 시작 직전에 역할 보유자를 다시 확인합니다.

## 안전 및 발송 제한

봇은 수신에 동의하지 않은 멤버에게 DM을 보내지 않으며, 서버 전체 무단 DM 기능은 제공하지 않습니다. 각 DM 첫 줄에 해당 수신자를 멘션한 뒤 공지 내용을 전달합니다. Discord API의 레이트리밋과 DM 개인 설정 때문에 대량 발송의 완료 시간이나 2초 내 전달을 보장할 수 없습니다. 봇은 API 제한을 따르며, 실패한 발송은 결과에 집계합니다.

불참자 기능은 사람을 추방하거나 서버에서 제거하지 않습니다. 명령어 결과는 실행 시점의 음성 채널 상태를 기준으로 하므로, 회의 도중 다시 확인하면 최신 상태를 볼 수 있습니다.
